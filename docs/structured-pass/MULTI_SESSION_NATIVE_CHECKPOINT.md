## What ran

heavy-run lock, process supervisor and pinned native clients. A network sandbox
allows localhost traffic only. The scripted API serves synthetic responses;
there are no provider calls or real project changes.

The first investigator leaves an accepted partial checkpoint. Its fresh
continuation reads that checked handoff and completes coverage. A third fresh
investigator completes its assigned coverage independently. The editor then
checks the union, reads the accepted handoffs, resolves a cited declaration,
and re-reads its edit fields before constructing the synthetic rename. No
coordinator-authored edit operation or semantic summary substitutes for this
handoff. The claims demonstrate identity and delivery, not semantic reasoning.

identical, deliberate bad-preimage refusals followed by the corrected request.
The reviewer requests changes, the editor publishes corrected notes, the
reviewer approves, and the same editor thread closes the pair. The final audit

Each is byte-identical to its authorized one-use claim. The offline correction
adds only their exact path class, for additions. Replaying the retained
snapshots then passes. Removing the tmux rule still fails on `pair/tmux.json`;
an unknown reviewer run file and a credential change still fail. No arg0
entries remain after the native turns.

The correction is outside the sealed attempt. It has not been used to resume
application or relabel the original run as successful. Application did succeed
in the separate direct-service rehearsal, with four expected files, but that
is narrower evidence than application through the complete native wrapper.

Cleanup took 0.111 seconds and found no survivors or tmux session. Both client
homes contain explicit dummy records only. The ten-invocation allowance is
fully used: two earlier fresh-context checks and these eight turns. Another
native recipe requires an explicit allowance; it is not an automatic retry.
