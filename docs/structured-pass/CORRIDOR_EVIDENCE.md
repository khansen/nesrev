# Whole-corridor evidence preparation

The previous capacity check measured a successful scripted reading path, but
priced only one complete RAM investigation. The live implementer correctly
stopped when the remaining ownership work could not fit that allowance. A
script's transport fit does not establish that the selected corridor fits.

## Authorized correction

Deliver one tooling change with three connected parts:

1. Derive an explicit corridor inventory from the retained assembler model and
   operator-selected scope roots/boundaries. Include every selected statement,
   its RAM operands and pointer bytes, producer/consumer evidence, called helper
   interfaces and the two selected analogue routines. Record unresolved control
   flow and indexed/indirect destinations; do not silently convert them to a
   complete static bound. Freeze this inventory before comparing transport.
2. Read RAM evidence for a set of addresses. Keep the unresolved-indirect sites
   once and each possible indexed site with its address membership. Retain each
   byte's direct facts, proof fields and uncertainty. Expansion must equal the
   existing per-byte view, modulo explicitly documented reading-only fields.
3. Offer a lean source-reading view with address, label, source text and stable
   record identity. Source bytes come from producer spans; instruction, scope
   and boundary facts come from the model. Existing full records and preimages
   remain the editing route. Preserve comments and pagination boundaries.

The existing fixed-ID operation reference explains both routes. Update the
task and guidance together: read the selected byte set once, retain all unknowns,
and fetch edit records when preparing edits. Do not require repeated complete
per-byte RAM summaries. Keep the current access controls, generation checks,
24 KiB response ceiling, lifecycle reserve and estimation margin.

## Acceptance

Provide a reusable preparation command that inventories the entire declared
corridor and measures the actual bridge responses needed for it. Price startup,
all local source, all selected RAM bytes, helper interfaces, both analogues,
measured unscripted overhead and a full next response. Include the existing
48K lifecycle reserve and at least 10% context-estimation margin. The bound
request must carry the resulting allowance and the inventory identity.

The unchanged service must fail the same complete-workload bar. Tests must catch
a missing RAM byte or helper, a lost or misclassified shared evidence row, wrong
generation, dropped source/comment text and incomplete capacity coverage. Test
both live roles and restored review where those reads are offered. Measure the
new routes through the bridge rather than pricing direct engine calls.

This is one offline correction and one final review round. Expected effort is
roughly one working day, with an inventory/baseline checkpoint before transport
implementation and a progress checkpoint after two hours. Reassess if the
inventory cannot express the selected corridor without a new analysis engine,
if the same failure repeats, or if a subproblem becomes a separate project.
No provider inference, live grant, semantic edit or application is authorized.
Declaration changes must be disclosed and admitted rather than disguised as an
unchanged pin. Retain the spent attempt and all failed checks.

If the complete corridor still does not fit after this change, do not build a
new live packet. Return the shortfall for a decision about separate investigation
and editing sessions. Do not reduce prose quality or weaken evidence to force a
pass. The alternative considered was continuing through the ordinary workflow;
the owner chose this correction to make structured work practical across games.

## Reading and editing routes

`navigate(view=source)` uses four columns: record identity, CPU address, label
and exact source text. Each page declares the columns. Comments remain separate
lexical records. A single selector supports label or segment bounds; an array
of up to 128 statement IDs selects the union of their label blocks. The reading
page allows 128 statements within 24 KiB, so a large owner selection need not be
repeated for dozens of very small pages. The existing editing views still allow
40 records and provide expression trees, locations and preimages.

`evidence(view=ram_set, address=[...])` accepts up to 128 unique addresses. It
coalesces equal original facts with their exact address membership. Categories,
pointer parts, alias proofs, certainty, native identities and every original
field survive expansion. Direct accesses are retained in full. Page-local
dictionaries include membership lists; per-address category counts appear on
the first page, and every page reports total grouped and expanded row counts.
No unknown is promoted to proof and no separate shared-set read is required.

## Preparation gate

Run the reusable command with `PYTHONPATH=scripts`:

```sh
python3 -B -m structured_pass.corridor_capacity \
  --session <prepared-session> --selection <measurement-selection.json> \
  --output <prepared-session>/corridor-capacity.json
```

The selection declares lexical root symbols and return boundaries, the RAM
ranges, vector and analogue routines, startup IDs, and measured context/pricing
inputs. Roots and memory ranges are operator scope, not discovered semantics.
The inventory derives every explicit operand and pointer byte, all global RAM
facts, direct/exact-base/pointer-byte access-owner blocks, and every direct
called helper interface. Out-of-root branch/jump targets prevent admission;
helpers' nested calls remain interface evidence, not a recursive gameplay pass.
Unknown indexed and indirect destinations remain in the full evidence set.

The command downloads the inventory's workload through the real bridge and
records every request, response and wire size. It checks complete page coverage
and includes both analogues, required startup inputs, unscripted overhead, a
maximum next response, the lifecycle reserve and estimation margin. Exit 3
means the workload does not fit. A report is not authority to call a provider.

Append `corridor_capacity.prompt(report)` to the task before assembling either
role. Pair preparation and verification require the report for a session with
a prepared startup budget. They check its code pins, initial generation,
regenerated inventory, startup selection, coverage, arithmetic and exact task
fragment. The pair pins the report file alongside its other inputs. Later
published generations do not reset the initial conversation allowance.

The command also has a legacy transport mode for comparison. The acceptance
negative control separately runs the frozen workload through the unchanged
merged bridge; it does not estimate an old implementation from a new one.
No live packet may be prepared from a failed complete-corridor price.

## Offline result: capacity stop

The frozen workload includes the selected root, both directly called helper
interfaces, every relevant explicit RAM operand, all direct/exact-base/pointer
access-owner blocks, and both analogue routines. The native output enumerates
16 distinct explicit RAM addresses; the earlier review prose said 17. The
retained enumeration, rather than that prose count, controls the measurement.
Indexed and indirect possibilities remain unknown; no runtime-access closure
is claimed.

The unchanged merged bridge needs 1,318,443 investigation response bytes for
this workload. Adding the observed unscripted overhead and the next response
requires 1,379,770 bytes, well above the allowance. This is the negative control
for the whole workload, not the earlier one-byte replay.

The corrected bridge delivers 1,421 source records, including overlapping reads
between the root and its access-owner contexts. Its RAM set stores 553 fact rows
that expand to all 4,814 original per-byte rows. The root's source response falls
to 5,132 bytes. All 16 bytes' RAM evidence falls from 516,318 to 124,386 bytes.
The local workload takes six logical requests; each analogue takes one. There
are 49 transport calls including startup.

The startup allocation increased from 78,000 to 82,000 tokens to cover the
larger reference and the delivered whole-corridor inventory. The total context
window, lifecycle reserve, estimation margin and observed unscripted overhead
were not reduced. New reading formats use the worst observed rate, 2.58 bytes
per token. Startup prose uses its measured conservative rate. This remains an
estimate, not proof of model comprehension or semantic completion.

The byte allowance fits, but the token-margin condition fails. The correction
therefore reaches the agreed stop-loss: **no new packet or live attempt**.
Separating investigation from editing requires a separate owner decision and
scope. There is no further capacity-tuning round in this authorization.
