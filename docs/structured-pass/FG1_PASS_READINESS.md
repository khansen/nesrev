## Checkpoint, stop rules and handoff

At two active hours, return the role-specific identity map, an unequal
round/sequence witness, the required code/declaration changes, preparation status
and layout observations obtained so far, plus a revised remaining estimate.
Continue only within the approved scope and bound. Stop and report if the
needed fix changes protocol semantics or access beyond the specifically
authorized published-candidate metadata, needs a new service operation,
worker, scheduler or transaction framework, or reveals a new admission failure.
Missing pins, an unexpected write, a failed native rehearsal, required runtime
evidence/policy writing, a repeated failure class or exhaustion of the allowance
also returns for a decision. Do not broaden the corridor or weaken acceptance.

Deliver a public neutral result and a private pinned live-request packet: exact
starting/input identities, complete role prompts and declarations, expected
changes, permitted application target, deadlines, invocation/response/usage
limits, review/rework allowance, owner-attention budget, stops and cleanup.
Do not infer these live budgets from the trivial admission task. Review any code
diff before publication, and require final-head CI on both runners before merge.

The owner then separately authorizes any required live preflight and **one
unscripted pass**, with logins outside the timed window. There is no automatic
pass 2. A static success leaves runtime integration, sustained compaction,
cross-game throughput and comparative cost unproven.
